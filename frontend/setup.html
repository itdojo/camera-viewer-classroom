Camera Viewer

Set up a Device

These steps take a Raspberry Pi from a blank SD card to a Camera playing in this Camera Viewer. Run the commands in a terminal on your own computer and over SSH on the Pi; keep this page open beside the Add Device Panel.

The test pattern needs no camera and makes a known-good Feed, so it is the quickest way to check the steps before any hardware is involved.

  1. Flash the OS

    Write Raspberry Pi OS (64-bit) to the SD card with Raspberry Pi Imager. In its settings, set a hostname, a username and password, and turn on SSH, because every later step reaches the Pi by that hostname and user.

    Not on a Pi? Any 64-bit Linux machine runs the test pattern; skip to step 2.

  2. Install Docker

    On the Pi, install Docker Engine with its Compose plugin by Docker's instructions for Debian, then follow its post-install steps so your user can run Docker without sudo. The kit runs entirely in containers, so Docker is all it adds to the OS. Check it answers:

    docker compose version

  3. Copy the kit to the Pi

    Download the Device Kit

    This instance serves the kit it was built with, so the two always match. From your computer, copy it to the Pi, log in there, and unpack it:

    scp ~/Downloads/device-kit.tar.gz <user>@<device>:~
ssh <user>@<device>
tar xzf device-kit.tar.gz
cd device-kit/usbcd device-kit/csicd device-kit/test-pattern

    If your browser unpacked the download into a device-kit folder, copy the folder instead: scp -r ~/Downloads/device-kit <user>@<device>:~

    The kit carries these steps too, for reading on the Pi: cat ~/device-kit/README.md

  4. Attach the camera and GPS receiver

    Plug the GPS receiver into a USB port now, so step 6 finds it. A Device without one still works; it just shows no Position on the map.

    There is no camera to attach: the test pattern draws its own picture.

    Plug the webcam in now, before anything looks for it. With more than one webcam attached, list them, since you name one in step 6:

    ls /dev/v4l/by-id/

    Each webcam is the name ending in -video-index0; an -index1 line beside it belongs to the same webcam.

    Power the Pi off first. Connect the module's ribbon only while the Pi is off; it finds the camera as it boots.

    Boot the Pi and check that it lists the camera. The kit's camera support finds it the same way:

    rpicam-hello --list-cameras

  5. Check the clock

    A wrong clock fails quietly. A Device whose clock is more than an hour off adds without complaint, but its Feeds never start.

    timedatectl

    Look for System clock synchronized: yes. If it says no, turn NTP on (it needs a time server the Pi can reach):

    sudo timedatectl set-ntp true

    With no time server in reach, set the clock by hand instead, to the time on your computer:

    sudo timedatectl set-ntp false
sudo timedatectl set-time "<YYYY-MM-DD HH:MM:SS>"

  6. Make the Device's certificate

    In the kit folder, run gen-cert.sh. It makes the Device's own certificate and password, finds the camera and GPS receiver, and prints what it made.

    ../gen-cert.sh

    Copy the lines under the green banner before you go on. They hold the password and fingerprint, and steps 8 and 9 need both. Paste them somewhere you can read beside this page. In your terminal they look like this, with your own values:

       ⛩ DEVICE CERTIFICATE READY ⛩
▌ INFO   Fingerprint:    <64 characters, 0–9 and a–f>
▌ INFO   Instance user:  viewer
▌ INFO   Password:       <32 characters, 0–9 and a–f>
▌ INFO   GNSS receiver:  /dev/serial/by-id/<your receiver>

    No GNSS receiver line means it found none: check the receiver is plugged in and run ../gen-cert.sh again. Scrolled past it all? Running it again prints the same values and changes nothing.

    With two webcams attached it won't guess: add --camera <name>, with one of the -video-index0 names from step 4.

    Run it on the Pi itself, because it also lists this Pi's camera devices for the container.

  7. Start the Device

    If gen-cert.sh printed a GNSS receiver line, start the Device with the gps profile, which runs the container that reads the receiver:

    docker compose --profile gps up -d

    With no receiver, leave the profile out:

    docker compose up -d

    The first start downloads the kit's images, which takes a few minutes. After that the Device starts by itself whenever the Pi boots.

    Stop a GPS Device with the profile too, because a plain down leaves the receiver's container running: docker compose --profile gps down

  8. Add it in Camera Viewer

    In the Add Device Panel, enter the Pi's address (its hostname with .local, or its IP address), a label (lowercase letters, digits and hyphens, such as cam-2), the username viewer and the password gen-cert.sh printed. Choose Check fingerprint.

  9. Compare the fingerprint

    Never confirm a fingerprint that doesn't match. A mismatch means the address reached some other machine, so stop and find out why.

    The fingerprint is how this Camera Viewer knows it is talking to your Device and nothing else. Compare the one the panel shows with the one gen-cert.sh printed, every character; the panel only adds a colon between pairs. If they match, confirm it.

    Lost the output? Run ../gen-cert.sh again in the same folder. It keeps the certificate and password and prints them again.

  10. Watch the Feed

    The Device's Camera now appears under Cameras. Tick Connect to put it on screen; it plays within a few seconds. If it shows Down, see the table below.

When you need more

Add a GPS receiver later

Plug the receiver in and run ../gen-cert.sh again so it finds the receiver, then start the Device with the gps profile as in step 7. It keeps the same certificate and password, so there is nothing new to confirm in Camera Viewer.

docker compose --profile gps up -d
Flip the picture

The kit folder's .env has a commented-out USB_CAMERA_FILTER line (add one if it's missing). Uncomment it and set it to hflip (left to right), vflip (top to bottom) or hflip,vflip (180°), then start the Device again as in step 7.

The kit folder's .env has CAMERA_HFLIP=true (left to right) and CAMERA_VFLIP=true (top to bottom) commented out (add them if they're missing). Uncomment one, or both for 180°, then start the Device again as in step 7.

Add a camera that isn't from the kit

A camera with its own RTSP stream, or a Device whose API can't be reached, goes in by URL under Add via RTSP in the Add Device Panel. A plain rtsp:// URL is unencrypted from the camera to this Camera Viewer, and the Camera is marked Unencrypted.

Troubleshooting

What you seeWhyFix
Feed shows Down, "Device clock wrong"The Pi's clock is more than an hour off.Fix it as in step 5. The Feed recovers within about 10 seconds.
The fingerprint doesn't matchThe address reached a different machine, or this Device's certificate was made again.Check the address is your Pi's. Run ../gen-cert.sh to see its fingerprint. Never confirm a mismatch.
Add Device can't reach the DeviceA wrong address, the Device not started, or a network that blocks it.On the Pi, docker compose ps should list it running. Try its IP address instead of .local. Ports 8322 and 9997 must be reachable from this Camera Viewer.
"certificate changed" after a rebuildA rebuilt Device has a new certificate.Compare the new fingerprint with what gen-cert.sh printed and trust it. If the rebuild changed its Cameras, remove the Device and add it again.
Camera module shows Down, and docker compose logs repeats camera_create()The ribbon is missing or badly seated.Power off, reseat the ribbon, and start the Device again.
